# Методическая карточка · C3-S5-LR19

> Материал преподавателя. Не публиковать как готовый ответ на студенческом стенде и не включать в шаблон отчёта.

## Цель и навык

- Цель: Зафиксировать контекст, варианты, решение и последствия в коротком ADR.
- Наблюдаемый навык: Объяснять решение нетехническому заказчику и сохранять причины отказа от альтернатив.
- Связь с лекцией: Architecture Decision Record, Защита решения.

## Ожидаемый результат

ADR на одну страницу и объяснение решения через факт, пользу, риск и проверку.

## Возможное правильное решение

ADR фиксирует сканирование как выбранный вариант, последствия для оборудования и обучения, а также триггер пересмотра при изменении потока.

## Допустимые варианты

Решение может отличаться от лидера матрицы только при новом явно зафиксированном факте.

## Типичные ошибки

- Пересказывать матрицу без последствий и условий пересмотра.
- Подмена исходного факта предположением без маркировки.
- Отсутствие связи между решением и способом проверки.
- Визуальный результат невозможно прочитать без устного объяснения.

## Подсказка для слабых студентов

Сформулируйте контекст без названий технологий, затем перечислите последствия для людей, данных и проверки.

Дайте студенту начать с одной строки «факт — источник — решение — проверка», затем предложите повторить структуру для остальных записей.

## Вопросы для обсуждения

- Какие последствия решения стоит сообщать заказчику в первую очередь?
- Как изменится решение при смене ограничения индивидуального варианта?
- Как доказать заказчику, что артефакт готов к следующему этапу?
