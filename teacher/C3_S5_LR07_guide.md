# Методическая карточка · C3-S5-LR07

> Материал преподавателя. Не публиковать как готовый ответ на студенческом стенде и не включать в шаблон отчёта.

## Цель и навык

- Цель: Перевести ключевые функции в язык пользовательской ценности и наблюдаемого результата.
- Наблюдаемый навык: Формулировать user story и критерии Given–When–Then без подмены требования макетом.
- Связь с лекцией: User story и критерии приёмки.

## Ожидаемый результат

Пять user story, по 2–3 критерия и связи с требованиями и правилами.

## Возможное правильное решение

Роль выбирается по ответственности за результат; ценность объясняет изменение процесса, а критерии включают позитивный и ограничительный сценарии.

## Допустимые варианты

Допустимы разные роли при доказанной ответственности и непротиворечивых критериях.

## Типичные ошибки

- Повторять в поле «ценность» текст цели или описывать элемент интерфейса.
- Подмена исходного факта предположением без маркировки.
- Отсутствие связи между решением и способом проверки.
- Визуальный результат невозможно прочитать без устного объяснения.

## Подсказка для слабых студентов

Если ценность звучит как «чтобы нажать кнопку», вернитесь к рабочей цели роли.

Дайте студенту начать с одной строки «факт — источник — решение — проверка», затем предложите повторить структуру для остальных записей.

## Вопросы для обсуждения

- Когда функция нужна системе, но не выражается естественной user story?
- Как изменится решение при смене ограничения индивидуального варианта?
- Как доказать заказчику, что артефакт готов к следующему этапу?
