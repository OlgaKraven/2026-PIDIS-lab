# Методическая карточка · C3-S5-LR17

> Материал преподавателя. Не публиковать как готовый ответ на студенческом стенде и не включать в шаблон отчёта.

## Цель и навык

- Цель: Проверить, что требования обеспечены данными, а элементы модели не лишены основания.
- Наблюдаемый навык: Строить двунаправленную матрицу трассировки и диагностировать разрывы.
- Связь с лекцией: Ревизия модели, Трассируемость.

## Ожидаемый результат

Матрица для всех ключевых требований и список непокрытых/лишних элементов.

## Возможное правильное решение

Требование о подтверждении маркировки связывается с операцией, ответственным, датой и статусом; лишний декоративный атрибут удаляется или обосновывается.

## Допустимые варианты

Тип покрытия может быть через правило, а не атрибут, если это явно обозначено.

## Типичные ошибки

- Считать связь с сущностью достаточной, не указывая нужный атрибут или правило.
- Подмена исходного факта предположением без маркировки.
- Отсутствие связи между решением и способом проверки.
- Визуальный результат невозможно прочитать без устного объяснения.

## Подсказка для слабых студентов

Для каждого требования задайте: «какие данные нужны, чтобы выполнить и доказать его?».

Дайте студенту начать с одной строки «факт — источник — решение — проверка», затем предложите повторить структуру для остальных записей.
