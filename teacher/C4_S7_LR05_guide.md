# Методическая карточка · C4-S7-LR05

> Материал преподавателя. Не публиковать как готовый ответ на студенческом стенде и не включать в шаблон отчёта.

## Цель и навык

- Цель: Спроектировать контракт API и документацию, достаточные для независимой реализации и проверки.
- Наблюдаемый навык: Определять endpoint, параметры, преобразование данных, ответы, ошибки, тесты и примеры запросов.
- Связь с лекцией: Проектная документация.

## Ожидаемый результат

Контракт endpoint, карта «данные → JSON», матрица статусов, примеры запроса/ответа и три тестовых сценария.

## Возможное правильное решение

GET /api/work-notes возвращает id, title_specialist, content, request_number и formatted_date; предусмотрены 200 с массивом или [], 400 для неверных параметров и 500 для внутренней ошибки.

## Допустимые варианты

Имена endpoint и полей могут отличаться, если контракт последователен, документирован и сохраняет требуемые преобразования.

## Типичные ошибки

- Описывать только успешный ответ или копировать структуру таблиц базы данных в публичный контракт.
- Подмена исходного факта предположением без маркировки.
- Отсутствие связи между решением и способом проверки.
- Визуальный результат невозможно прочитать без устного объяснения.

## Подсказка для слабых студентов

Начните с одного запроса: вход → выборка → преобразование → ответ → ошибка; затем превратите цепочку в таблицу и тесты.

Дайте студенту начать с одной строки «факт — источник — решение — проверка», затем предложите повторить структуру для остальных записей.
