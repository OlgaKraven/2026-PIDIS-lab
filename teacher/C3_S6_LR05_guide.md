# Методическая карточка · C3-S6-LR05

> Материал преподавателя. Не публиковать как готовый ответ на студенческом стенде и не включать в шаблон отчёта.

## Цель и навык

- Цель: Создать небольшой согласованный набор компонентов для проекта.
- Наблюдаемый навык: Определять визуальные токены и обязательные состояния интерактивных компонентов.
- Связь с лекцией: Дизайн-система и доступность.

## Ожидаемый результат

Лист токенов и 6–8 компонентов со всеми нужными состояниями и подписями.

## Возможное правильное решение

Для поля показаны normal/focus/filled/error/disabled; для кнопки — primary/secondary/danger и состояния взаимодействия.

## Допустимые варианты

Допустима иная палитра при достаточном контрасте и последовательных токенах.

## Типичные ошибки

- Показывать только идеальное обычное состояние компонента.
- Подмена исходного факта предположением без маркировки.
- Отсутствие связи между решением и способом проверки.
- Визуальный результат невозможно прочитать без устного объяснения.

## Подсказка для слабых студентов

Начните с токенов: шрифт, интервалы, радиус, цвета; затем примените их ко всем компонентам.

Дайте студенту начать с одной строки «факт — источник — решение — проверка», затем предложите повторить структуру для остальных записей.

## Вопросы для обсуждения

- Как доказать заказчику, что артефакт готов к следующему этапу?
