# Методическая карточка · C3-S5-LR03

> Материал преподавателя. Не публиковать как готовый ответ на студенческом стенде и не включать в шаблон отчёта.

## Цель и навык

- Цель: Извлечь проектно значимые утверждения из нескольких документов заказчика.
- Наблюдаемый навык: Отличать требование от справочного факта и сохранять ссылку на источник.
- Связь с лекцией: Источники требований.

## Ожидаемый результат

Реестр из 12–16 утверждений с точными источниками и отметкой неопределённости.

## Возможное правильное решение

Нельзя утверждать автоматический приоритет по желаемой дате: документ показывает данные, но не правило обработки.

## Допустимые варианты

Допустимы разные границы реестра, если справочные факты отделены от требований и все выводы трассируются.

| Обоснование | Решение связано с подтверждённым фактом и не добавляет неизвестные условия. |
| Критерий проверки | Требование можно проверить по процитированному фрагменту или полю формы. |
| Доказательство | Заполненный артефакт и ссылка на строку исходных данных. |

## Типичные ошибки

- Додумывать поведение системы по названию столбца без фиксации допущения.
- Подмена исходного факта предположением без маркировки.
- Отсутствие связи между решением и способом проверки.
- Визуальный результат невозможно прочитать без устного объяснения.

## Подсказка для слабых студентов

Для каждого кандидата задайте вопрос: «Что должна делать система или что должно оставаться истинным?».

Дайте студенту начать с одной строки «факт — источник — решение — проверка», затем предложите повторить структуру для остальных записей.

## Вопросы для обсуждения

- Какие требования чаще скрыты в пустых и повторяющихся полях формы?
- Как изменится решение при смене ограничения индивидуального варианта?
- Как доказать заказчику, что артефакт готов к следующему этапу?
