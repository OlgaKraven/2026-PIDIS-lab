# Методическая карточка · C3-S5-LR03

> Материал преподавателя. Не публиковать как готовый ответ на студенческом стенде и не включать в шаблон отчёта.

## Цель и навык

- Цель: Исправить некорректные требования и описать ключевые функции через пользовательские истории с критериями приёмки.
- Наблюдаемый навык: Делать требования атомарными и проверяемыми, не добавляя неизвестных фактов, и формулировать критерии Given–When–Then.
- Связь с лекцией: Качество требований, User story и критерии приёмки.

## Ожидаемый результат

Не менее 8 переработанных требований, 4–5 пользовательских историй и по 2–3 проверяемых критерия приёмки для каждой истории.

## Возможное правильное решение

Неизмеримые характеристики без данных возвращаются на уточнение; подтверждённые функции оформляются как истории ролей с позитивными и ограничительными сценариями.

## Допустимые варианты

Допустимы разные редакции и роли, если они подтверждены источниками, сохраняют цель и допускают однозначную проверку.

## Типичные ошибки

- Подставлять правдоподобные числа, описывать элементы интерфейса вместо ценности или повторять требование в критерии.
- Подмена исходного факта предположением без маркировки.
- Отсутствие связи между решением и способом проверки.
- Визуальный результат невозможно прочитать без устного объяснения.

## Подсказка для слабых студентов

Выделите союзы, оценочные слова и скрытые местоимения, затем проверьте роль, ценность и результат каждой истории.

Дайте студенту начать с одной строки «факт — источник — решение — проверка», затем предложите повторить структуру для остальных записей.
