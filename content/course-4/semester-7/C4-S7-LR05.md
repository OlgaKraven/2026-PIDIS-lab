# C4-S7-LR05 · Проектирование API и проектная документация

Семестр 7. Максимум 6 баллов.

Спроектировать контракт API и документацию, достаточные для независимой реализации и проверки.

## Контракт API

Контракт описывает метод, путь, параметры, структуру ответа и ошибки. В этой работе API проектируется, программирование не требуется. Исходный учебный путь GET /api/work-notes сохраняется. Необязательный requestId — положительное целое число. Отсутствие найденных данных даёт 200 и пустой массив, а неверный параметр — 400.

## Преобразование и тест

Сопоставьте каждое поле JSON с источником или формулой. content сохраняется без изменения; дату UTC переводят в DD.MM.YYYY по явно заданному правилу без часового сдвига. В исходном учебном контракте title_specialist соединяется через длинное тире, request_number добавляется из заявки. Это расширение учебного кейса; в экзаменационном контракте имена и разделитель сверяют отдельно. Ошибка 500 не раскрывает стек, SQL и секреты.

## Действия

1. Опишите endpoint. Задайте метод, путь, параметр, успешный и ошибочные ответы. Проверка: Отсутствующий параметр отличается от пустого и неверного.
2. Постройте преобразование. Сформируйте JSON для заданных запросов и порядок сортировки. Проверка: Каждое поле прослеживается к исходной записи.
3. Подготовьте тесты. Проверьте 200, пустой массив, 400, контролируемый 500 и структуру JSON. Проверка: Ожидаемый результат конкретен для каждого запроса.
4. Согласуйте документацию. Укажите границы ответственности, допущения и изменения связанных документов. Проверка: Документ достаточен для независимой реализации без устных договорённостей.

Выдаваемый архив содержит условия выбранного варианта, все таблицы CSV и собственную форму DOCX.
