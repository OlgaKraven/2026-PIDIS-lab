# Учебный сквозной кейс 4 курса: Field Service «Выезд»

> Все названия, роли, процессы и числа в этом файле являются данными учебной задачи и не описывают реальную организацию.

## Пакет заказчика

Учебная сервисная служба «Выезд» принимает заявки на обслуживание оборудования, назначает специалиста, фиксирует выполненные работы, заметки специалистов и использованные запасные части. В пакет входят брифинг, заявка на выезд, карточка оборудования, журнал работ, заметки специалистов, справочник запчастей и список пользователей.

| Источник | Поля/фрагмент | Проектный вопрос |
|---|---|---|
| Заявка | номер, клиент, адрес, оборудование, описание, приоритет | может ли заявка содержать несколько единиц оборудования? |
| Карточка оборудования | серийный номер, модель, дата ввода, клиент | что происходит при передаче оборудования другому клиенту? |
| Журнал работ | заявка, специалист, начало, завершение, результат | допускается ли несколько выездов по одной заявке? |
| Заметка специалиста | id, заявка, автор, заголовок, содержание, created_at | какие поля и преобразования должны попасть в публичный API? |
| Использование запчастей | работа, запчасть, количество | требуется связующая сущность для M:N |
| Пользователь | логин, технический профиль, бизнес-роль, статус, попытки входа | логин уникален, три ошибки блокируют запись |

## Роли

- диспетчер создаёт и назначает заявки;
- специалист видит назначенные заявки и закрывает выполненную работу;
- администратор управляет пользователями и снимает блокировку;
- руководитель просматривает сводные сведения без редактирования операций.

Для сценария, приближенного к КИМ, используются технические профили `Admin` и `User`. Они не заменяют бизнес-роли: доступ к заявкам и работам определяется отдельной матрицей полномочий.

## Контрольные условия

1. Логин пользователя уникален.
2. После трёх последовательных ошибок в пароле или сборке проверочного изображения запись блокируется.
3. Снятие блокировки и изменение роли журналируются.
4. Количество использованной запчасти — положительное целое значение.
5. Закрытая работа имеет дату завершения и результат.
6. Каждая заметка связана с заявкой и автором; дата создания хранится однозначно.
7. Мобильный клиент получает заметки только через документированный API, а не через прямой доступ к базе данных.

## Учебный контракт API для LR05

В рамках МДК API **проектируется, но не программируется**. Студент описывает контракт так, чтобы разработчик мог независимо реализовать его, а тестировщик — проверить.

### Endpoint

- метод и путь: `GET /api/work-notes`;
- необязательный параметр: `requestId` — положительный целочисленный идентификатор заявки;
- источники данных: `WorkNote`, `User`, `ServiceRequest`;
- сортировка: от новых заметок к старым по `created_at`.

### Преобразование ответа

| Поле JSON | Источник/правило |
|---|---|
| `id` | идентификатор `WorkNote` |
| `title_specialist` | заголовок заметки + `" — "` + логин автора |
| `content` | содержание заметки |
| `request_number` | номер связанной заявки |
| `formatted_date` | `created_at` в формате `ДД.ММ.ГГГГ` |

### Статусы и проверки

| Сценарий | Статус | Тело ответа |
|---|---:|---|
| данные найдены | 200 | массив объектов по контракту |
| данных нет | 200 | пустой массив `[]` |
| `requestId` имеет неверный формат или диапазон | 400 | объект с понятным кодом и сообщением ошибки |
| ошибка доступа к данным или внутренняя ошибка | 500 | нейтральный объект ошибки без технических подробностей |

Минимальный набор проектных тестов: успешный ответ 200, ответ 500 по контролируемому сбою и проверка корректной структуры JSON. Дополнительно рекомендуется проверить пустой массив и ошибочный `requestId`.

## Индивидуальные ситуационные варианты A–AD

Преподаватель назначает один вариант на студента. Вариант применяется ко всему комплекту работ 7 семестра: анализу документов, модели данных, экрану авторизации, матрице прав, контракту API и проектной документации. Студент обязан отделять подтверждённый факт от вопроса заказчику и проектного решения.

| Вариант | Роль фокуса | Ситуация и неполные данные | Проектное противоречие или решение |
|---|---|---|---|
| A | диспетчер | в одной заявке перечислены две единицы оборудования, но форма содержит одно поле серийного номера | одна заявка на выезд против отдельного учёта каждого оборудования |
| B | специалист | по одной заявке потребовались первичный и повторный выезды | единый результат заявки против истории нескольких выполненных работ |
| C | менеджер клиента | оборудование передано другому клиенту, дата передачи известна не во всех документах | текущий владелец против сохранения владельца на дату прошлой работы |
| D | диспетчер | в двух карточках совпадает серийный номер, но различаются модели | автоматическое объединение против запроса на подтверждение дубликата |
| E | руководитель | на один сложный выезд назначены два специалиста | один ответственный против фиксации вклада каждого исполнителя |
| F | специалист | вместо указанной запчасти использован согласованный аналог | точность первоначального плана против фактического состава работ |
| G | кладовщик запчастей | в документе списания количество больше доступного остатка | закрытие работы против запрета отрицательного остатка |
| H | диспетчер | клиент просит повысить приоритет после назначения специалиста | срочность клиента против уже согласованного расписания |
| I | специалист | доступ к оборудованию на объекте не предоставлен | завершение выезда против невозможности выполнить работу |
| J | диспетчер | клиент отменил заявку, когда специалист уже выехал | отмена заявки против сохранения факта и результата выезда |
| K | специалист | на объекте отсутствует сеть, сведения синхронизируются позднее | работа офлайн против актуальности статуса для диспетчера |
| L | специалист | фотография результата может содержать персональные данные клиента | доказательство выполненной работы против минимизации сохраняемых данных |
| M | администратор | новый пользователь выбрал логин, уже занятый заблокированной записью | удобный логин против требования уникальности |
| N | руководитель | диспетчер временно исполняет обязанности руководителя | непрерывность процесса против постоянного расширения прав |
| O | администратор | запрос на разблокировку передан коллегой пользователя | быстрое восстановление доступа против проверки личности владельца записи |
| P | диспетчер | на старом оборудовании отсутствует читаемый серийный номер | регистрация заявки против риска создать дубликат оборудования |
| Q | специалист | повторный выезд выполняется по гарантии, но причина повторения не указана | бесплатная гарантийная работа против подтверждения её основания |
| R | специалист | часть работ выполнена, а заказанная запчасть ещё не поступила | частичное завершение против правила закрытой работы |
| S | руководитель | к работе привлечён внешний специалист без постоянной учётной записи | доступ подрядчика против минимальных и ограниченных по сроку прав |
| T | диспетчер | заявка создана в одном часовом поясе, специалист работает в другом | локальное отображение времени против однозначной хронологии событий |

| Y | аудитор | требуется восстановить, кто и когда изменил роль администратора | текущие права против проверяемой истории изменений доступа |
| Z | диспетчер | после закрытия заявки клиент сообщил об ошибке в результате | неизменность закрытого документа против контролируемой корректировки |

| AB | администратор | три неуспешных попытки возникли одновременно на двух устройствах | последовательность событий против конкурентного обновления счётчика |
| AC | руководитель | специалист увольняется, но за ним остаются незакрытые заявки | запрет доступа бывшего сотрудника против передачи ответственности |
| AD | диспетчер | клиент сообщает одну неисправность в письме и другую по телефону | единое описание заявки против сохранения источников и уточнений |
